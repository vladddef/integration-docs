# `GET https://t.trklinkx.com/click`

Server-to-server эндпоинт для отправки лида без формы на лендинге. Проверяет лид, проверяет его на дубликаты и регистрирует, после чего отвечает редиректом. Результат регистрации возвращается в заголовке ответа `X-Conversion-Result`.

- **URL:** `https://t.trklinkx.com/click`
- **Метод:** `GET`, параметры в query string
- **Авторизация:** query-параметр `sub30` (ваш API-ключ)
- **Результат:** заголовок ответа `X-Conversion-Result`. По HTTP-коду и телу успех от ошибки не отличить.
- **Редиректы:** `https://t.trklinkx.com/click` перенаправляет запрос на наш сервер, который делает ещё один редирект на веб-страницу. Вы **обязаны следовать редиректам** (например, `curl -L`), иначе запрос до нас не дойдёт и лид не будет зарегистрирован. Заголовок есть и в нашем ответе `302`, и на конечной странице, поэтому неважно, остановитесь ли вы на `302` или пройдёте до конца.

## Запрос

```
GET https://t.trklinkx.com/click?pid=11&offer_id=12716&sub1=6ade9d6a325c9f0001b40fdc&sub9=Ion%20Popescu&sub12=%2B40751382418&sub30=KEY&ip=203.0.113.7
```

Следуйте за редиректами и прочитайте заголовок `X-Conversion-Result` последнего ответа. Например, через `curl`:

```
curl -s -D - -o /dev/null -L "https://t.trklinkx.com/click?pid=11&offer_id=12716&sub1=6ade9d6a325c9f0001b40fdc&sub9=Ion%20Popescu&sub12=%2B40751382418&sub30=KEY" | grep -i x-conversion-result
```

### Обязательные параметры

Параметр, который отсутствует, пустой или передан несколько раз (`?pid=1&pid=2`), считается отсутствующим.

| Параметр | Описание |
|---|---|
| `sub30` | Активный API-ключ, выданный вам. |
| `pid` | ID паблишера / источника трафика. |
| `offer_id` | ID оффера. Также входит в ключ дубликата. |
| `sub9` | Имя клиента. Минимум 2 символа и минимум одна буква (латиница или кириллица). |
| `sub12` | Телефон клиента. Любой формат, но после удаления нецифровых символов должно остаться 7–15 цифр. |
| `sub1` | ID клика визита. |

### Необязательные параметры

| Параметр | Описание |
|---|---|
| `ip` | IP клиента. Если не передан, используется IP из заголовков запроса (`X-Real-IP`, затем последняя запись `X-Forwarded-For`). |

Любой другой параметр принимается и записывается в лог.

## Ответ

```
HTTP/1.1 302 Found
Location: /landing/typ?... | /landing/form?...
X-Conversion-Result: { "status": "ok" | "error", "data": { ... } }
```

`Location` — страница, на которую отправляется посетитель (`/landing/typ?...` для принятого лида, иначе `/landing/form?...`). `X-Conversion-Result` — результат одной строкой JSON, присутствует всегда: и в этом `302`, и на той странице. Не-ASCII символы в нём экранируются как `\uXXXX`.

### Примеры ошибок

При ошибке `status` равен `"error"`, а код ошибки лежит в `data.error`. Каждый пример ниже — это значение заголовка `X-Conversion-Result`.

| `data.error` | Когда | Пример |
|---|---|---|
| `security` | `sub30` отсутствует, неизвестен или отключён. | `{"status":"error","data":{"error":"security"}}` |
| `ban` | Ваш IP заблокирован. | `{"status":"error","data":{"error":"ban"}}` |
| `nophone` | Не передан `sub12`. | `{"status":"error","data":{"error":"nophone"}}` |
| `data` | Не передан обязательный параметр, либо телефон или имя в неверном формате. В `bad` перечислены проблемные поля: имена параметров (`pid`, `sub1`, `sub9`, ...) для отсутствующих, `phone` или `name` для неверного формата. | `{"status":"error","data":{"error":"data","bad":["phone"]}}` |
| `duplicate` | Тот же оффер + телефон уже отправляли в течение 14 дней. `id` — ID исходного лида. | `{"status":"error","data":{"error":"duplicate","id":1596426}}` |
| `connection_timeout` | Лид не удалось доставить вовремя. Временная ошибка, повторите позже. | `{"status":"error","data":{"error":"connection_timeout"}}` |
| `internal` | Непредвиденная ошибка на нашей стороне. | `{"status":"error","data":{"error":"internal"}}` |

## Примечания к поведению

- **Порядок проверок:** чёрный список IP → `sub30` → обязательные параметры → формат телефона и имени → проверка дубликата → регистрация.
- **Дубликаты:** ключ — это оффер плюс телефон без всех нецифровых символов, поэтому `+40 751 382 418` и `40751382418` совпадают. В течение 14 дней после успешной отправки тот же оффер + телефон возвращается как `duplicate`.
- **Логирование:** каждый вызов логируется, при этом API-ключ заменяется на `[redacted]`. Имя и телефон клиента в логе остаются.
- **Повторы:** временными могут быть только `connection_timeout` и `db`. Для них подождите и повторите запрос. Повтор после настоящего успеха вернёт `duplicate`.
