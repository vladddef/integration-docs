# `GET /landing/track-postback`

Server-to-server эндпоинт для отправки лида без формы на лендинге. Проверяет лид, проверяет его на дубликаты и регистрирует, после чего делает редирект, как в обычном потоке лендинга. Результат регистрации возвращается в заголовке ответа `X-Conversion-Result`.

- **URL:** `/landing/track-postback`
- **Метод:** `GET`, параметры в query string
- **Авторизация:** query-параметр `api_key`
- **Всегда HTTP `302`** с заголовком `Location`. Тело читать не нужно: успех и ошибка различаются по заголовку `X-Conversion-Result`, а не по HTTP-коду.

## Запрос

```
GET /landing/track-postback?api_key=KEY&pid=5345&offer_id=13425&cpa_offer_id=3920&sub9=Ion%20Popescu&sub12=%2B40751382418&sub1=6ade9d6a325c9f0001b40fdc&ip=203.0.113.7
```

### Обязательные параметры

Параметр, который отсутствует, пустой или передан несколько раз (`?pid=1&pid=2`), считается отсутствующим.

| Параметр | Описание |
|---|---|
| `api_key` | Активный API-ключ, выданный вам. |
| `pid` | ID паблишера / источника трафика. |
| `offer_id` | ID оффера на стороне источника трафика. |
| `cpa_offer_id` | ID оффера на стороне CPA. Также входит в ключ дубликата. |
| `sub9` | Имя клиента. Минимум 2 символа и минимум одна буква (латиница или кириллица). |
| `sub12` | Телефон клиента. Любой формат, но после удаления нецифровых символов должно остаться 7–15 цифр. |
| `sub1` | ID клика визита. |

### Необязательные параметры

| Параметр | Описание |
|---|---|
| `ip` | IP клиента. Если не передан, используется IP из заголовков запроса (`X-Real-IP`, затем последняя запись `X-Forwarded-For`). |

Любой другой параметр принимается и записывается в лог.

## Ответ

```
HTTP/1.1 302 Found
Location: /landing/typ?name=...&phone=...&pixel=...
X-Conversion-Result: { "status": "ok" | "error", "data": { ... } }
```

- **`Location`:** `/landing/typ?...`, если лид принят (включая повтор уже зарегистрированного лида), `/landing/form?...` при любом другом исходе. Те же адреса, что и у `/landing/conversion-params`.
- **`X-Conversion-Result`:** результат одной строкой JSON, присутствует всегда. Не-ASCII символы экранируются как `\uXXXX`, поэтому значение содержит только ASCII.
- **Заголовок есть и на конечной странице.** Редирект передаёт результат в query-параметре `conversion_result` внутри `Location`, а `/landing/typ` и `/landing/form` повторяют его как `X-Conversion-Result` в своём ответе. Поэтому клиент, который идёт по редиректу, всё равно видит результат. Повторяется только корректный результат (`status` равен `ok` или `error`, плюс `data`).

## Примечания к поведению

- **Порядок проверок:** чёрный список IP → `api_key` → обязательные параметры → формат телефона и имени → проверка дубликата → регистрация.
- **Дубликаты:** ключ — это `cpa_offer_id` плюс телефон без всех нецифровых символов, поэтому `+40 751 382 418` и `40751382418` совпадают. В течение 14 дней после успешной отправки тот же оффер + телефон возвращается как `duplicate`.
- **Логирование:** каждый вызов логируется как `track-postback query: {...}`, при этом `api_key` заменяется на `[redacted]`. Имя и телефон клиента в логе остаются.
- **Повторы:** временными могут быть только `connection_timeout` и `db`. Для них подождите и повторите запрос. Повтор после настоящего успеха вернёт `duplicate`.
